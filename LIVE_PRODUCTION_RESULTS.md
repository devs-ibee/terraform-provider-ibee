# Initial production Terraform validation — 2026-09-28

**Follow-up:** [CROSS_CLIENT_RESULTS.md](CROSS_CLIENT_RESULTS.md) is the current release assessment. Cloud VM read/import/destroy is now fixed and verified; current coverage is 15/34 lifecycle passes, 4 blocked and 15 not production lifecycle tested. The original GPU monthly-catalog interpretation below has been corrected.

The pushed provider branch was built locally and tested with real Terraform against the production public API in a user-selected Production workspace. The user set a ₹2,000 maximum for disposable tests. The temporary API token, organization/workspace identifiers, generated S3 secret, and Terraform states are excluded from this public report. No portal form created infrastructure; the portal was used for catalog quotes, billing, and Activity Logs.

## Result

The read-only preflight passed: billing admission allowed in INR, with three compute sites, one available networking site, 13 cloud plans, six cloud images, three GPU plans and one GPU image. The first combined preflight returned HTTP 403, then a repeat passed. Exact provider-signature single-route reads also passed. The cause of that first denial was not established.

All five data-source types passed the read-only preflight. None of the three Terraform actions was exercised in production. Development test evidence remains in the other live reports and must not be counted as production validation.

## Cleanup and logs

Terraform destroyed every test resource it could manage and its managed states ended empty. Independent production GETs returned 404 for the test VPC, firewall group, buckets, CDN distribution, cloud VM and reserved IP; the S3 credential was `revoked`. Secret deletion/archive intentionally retains service history and names. Block creation left no volume. One test-harness edit accidentally changed the bucket's Object Lock configuration and proposed replacement while the bucket contained the test HTML; the service correctly refused deletion with 409. The configuration was restored without replacing the bucket, and subsequent CDN changes and cleanup passed.

The production portal displayed matching successful Activity Log entries for network, storage, CDN, secret, VM and reserved-IP mutations, plus the expected failed bucket deletion attempt. The actor column varied between `Unknown`, `Network service`, `virtualization-engine`, `API`, and `secret-store`; it did not consistently identify the API token. This confirms selected mutation logging, not logging of every API read or reliable token attribution.

The billing summary displayed ₹0.00 current September usage after cleanup. That is a snapshot, not final settlement; delayed metering/invoicing was not independently checked. No credits were purchased or redeemed, no payments were submitted, and no pre-existing customer resources were changed.

## Work remaining before a release

1. **Repair VM billing readback and deletion.** The production VM GET must return the selected term consistently, including `commitment_period` and authoritative price fields, or the provider must safely normalize an explicitly uncommitted hourly response. Keep rejection of ambiguous monthly commitments. Add a real contract fixture for the observed production shape and ensure a failed refresh cannot strand a billable VM from Terraform cleanup. Re-run create/read/no-change/import/destroy and VM power, snapshot, backup and attachment tests after this fix.
2. **Repair block storage access and discovery.** Trace the production 403 at the gateway/service with the token's Block Storage permissions, publish a working plan catalog, and align SKU/site/size selection with the portal. Repeat a quoted 10 GB create/read/grow/delete and attachment against a disposable VM.
3. **Repair the workspace S3 TLS endpoint.** Verify DNS, ingress and certificate for the documented hostname, then run scoped upload/list/download/delete and a successful-access-to-denied-access check after revocation.
4. **Trace GPU create authorization/admission.** The follow-up confirmed priced/selectable hourly plans but an empty HTTP 403 on create. Correlate that failure at the gateway. The prior development pass separately found a monthly-based gateway admission calculation for hourly GPU requests.
5. **Complete the remaining product matrix.** NAT and forwarding need an authoritative price and disposable VPC; VM/node/firewall/IP attachments and cloud/GPU backup/snapshot/power require a working disposable VM; load balancers need a published price and reachable test backend; bucket retention needs an empty lock-enabled test bucket; CDN custom origin currently returns 404, while custom domains require owned test DNS. Portal-only registry, email, SSH/ISO, DNS, bare metal and standalone certificate gaps still need public lifecycle contracts before claiming Terraform support.
6. **Fix Activity Log identity.** Propagate the gateway's verified principal/credential identity into product events and async jobs, and record API origin without storing the token secret. Confirm production deployment and negative/error cases after implementation.

The provider remains on the `codex/terraform-platform-provider` branch. Merge or Registry publication should follow the contract fixes and a clean production lifecycle pass for the features being advertised.
