# ibee_secret_identity (Resource)

A Secret Store application identity (AppRole or Kubernetes) that applications use to read secrets. Creation also grants it a scope on store_id; use ibee_secret_identity_scope for other stores. The API decides what is allowed. Each read of an AppRole identity's login details mints a new secret ID, so the provider reads them once, at creation, and keeps role_id and secret_id in state (secret_id is sensitive but not encrypted by the provider; use an encrypted state backend). Imports leave them null. Destroy permanently deletes the identity, its scopes and its sessions. Import with STORE_ID/IDENTITY_ID.

## Example Usage

```terraform
resource "ibee_secret_identity" "billing" {
  store_id          = "STORE_ID"
  name              = "billing-service"
  auth_method       = "approle"
  token_policy_mode = "read_only"
}

# role_id and secret_id are read once, at creation.
output "billing_role_id" {
  value = ibee_secret_identity.billing.role_id
}

output "billing_secret_id" {
  value     = ibee_secret_identity.billing.secret_id
  sensitive = true
}
```

| `auth_method` | `string` | Required | approle or kubernetes. |

| `role_id` | `string` | Read-only | AppRole role ID, read once at creation. |
| `secret_id` | `string` | Read-only, Sensitive | AppRole secret ID, returned once at creation and stored in state. Null after import and for Kubernetes identities. |
| `status` | `string` | Read-only | active or disabled, as the API reports. |
| `store_id` | `string` | Required | Store the identity is created in and first granted access to. |
| `token_policy_mode` | `string` | Optional, Defaulted | read_only or read_write. The API default applies when omitted. The public API has no operation to change it, so a change replaces the identity (and mints new login details). |
